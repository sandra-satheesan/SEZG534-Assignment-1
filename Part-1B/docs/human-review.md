# US5 Human Review Record

Automated evaluation is evidence, not acceptance. A reviewer must inspect the
feature specification, the versioned case corpus, aggregate metrics, every
case and run result, failures, and limitations before recording a decision.

## Review procedure

1. Confirm the case-set version and digest match the evaluation report.
2. Confirm all nine FR-014 categories and all four FR-018 semantic dimensions
   are represented.
3. Inspect aggregate metrics, independent hard gates, per-case results, and
   failed properties.
4. Review repair results against the same unchanged case-set digest.
5. Record limitations and an explicit `approved` or `rejected` decision.

An `approved` decision is valid only after the reviewer has completed the
evidence review. Passing automated thresholds alone must not create or imply
human acceptance.

## Usability review package for T059

### Introduction for reviewers

This service interprets one natural-language reminder request. It returns
structured information about the reminder title, timing, recurrence, and
follow-up instructions, or asks for clarification when essential information
is missing or ambiguous. It does not schedule reminders, persist them, or
send notifications.

The review checks whether a person can understand the returned interpretation,
not whether the service has performed any reminder action.

- All five reviewers understood that the reminder is to **call Rahul**.

#### Scenario 2: “Remind me to submit my assignment next Monday evening”

- All five reviewers understood that the reminder is to **submit an

- Reviewers interpreted the schedule as **Monday evening, 9 November 2026**.
- All reviewers identified it as a **single reminder** with **no recurrence or

- All five reviewers understood that the reminder is to **take medicine**.

  **no end date**.
- All reviewers agreed that **no clarification is required**.

#### Additional clarification scenario

Request: “Remind me to submit my report sometime next week.”

Assistant response: “I need clarification. Which day and time next week would
you like to be reminded?”

All five reviewers answered **Yes** when asked whether the response made
sense. They identified the missing information as the exact day of the week,
the specific reminder time, and a precise reminder schedule. All five
reviewers answered **Yes** when asked whether they would prefer this
clarification rather than a guessed date and time.

The reviewers agreed that asking for clarification is preferable to making
assumptions. This feedback concerns the supplied clarification scenario and
response; it is not evidence that the actual Groq output for NLR-004 or any
other scenario was reviewed.

### Exact reviewer instructions

1. Record your reviewer identifier and review date before starting. Do not
   infer or copy another reviewer's answers.
2. Read only the scenario request and reference context before viewing its
   result.
3. Before opening the result, write your own short answer for the title,
   timing, recurrence/follow-up, and whether clarification is required.
4. Inspect the returned structured result and answer the same four questions
   using only the result. Note any field that is missing, invented, or
   difficult to understand.
5. Mark each scenario pass only when all four answers are correct:
   title, timing, recurrence/follow-up, and clarification status.
6. Record the scenario ID and the exact result artifact, test output, or
   report location used as evidence. Do not mark an evidence reference that
   was not actually inspected.
7. Record usability problems and limitations separately from correctness
   failures. Do not change the result or reinterpret an unresolved value as
   resolved.
8. Submit the completed form to the review owner. The review owner completes
   the consolidated table only from submitted forms.

### T059 pass rule

T059 uses a proportionate evidence rule rather than a fixed participant count
or numerical reviewer threshold. It is complete when the selected usability
scenarios, available participant observations, limitations, and the separation
between participant feedback and application evidence are documented. This
record satisfies that scope for NLR-001–003 and the additional clarification
scenario. NLR-004 remains a provider failure, and no participant results are
claimed for NLR-004, NLR-005, or NLR-009. T060 remains the separate human
acceptance decision.
